## 1. はじめに＆設計思想

**Yukinary (YKN)** は、外部のCランタイム（libc/msvcrt）、LLVM、サードパーティのリンカーに依存することなく、Windows（PE32+）およびLinux（ELF64）のネイティブマシンコードを直接生成する自己完結型（セルフホスティング）の次世代システムプログラミング言語です。

### 主な特徴:
* **ダイレクトマシンコード生成:** 中間Cファイルやアセンブラを介さず、超高速にバイナリを出力。
* **GCなしのメモリ安全性:** コンパイル時にポインタの生存期間、NULL安全性、Use-After-Freeを徹底検証。
* **ネイティブ日本語構文:** 日本語のキーワードを直接コンパイラレベルで解析。
* **自己修復（Self-Healing）機能:** セミコロンの欠落、NULL参照などを自動補正しビルドを保護。
* **16KBの内蔵ニューラルモデル:** BitNet 1.58b Ternary Transformerをバイナリ内に直接内包（0.1msの応答速度）。

## 3. 多言語文法システム

Yukinaryでは、完全に日本語のキーワードを使用してプログラムを記述できます：

```ykn
関数 合計を計算(値: 整数) -> 整数 {
    変数 結果: 整数 = 値 * 2;
    もし 結果 > 100 ならば {
        戻す 結果;
    } それ以外 {
        戻す 0;
    }
}
```

### 日本語キーワード対応表:
* `関数` — 関数の宣言
* `変数` — 変数の宣言
* `もし` .. `ならば` .. `それ以外` — 条件分岐
* `繰り返す` — ループ処理
* `戻す` — 戻り値
* `構造体` — 構造体定義
* `列挙型` — 列挙型（代数的データ型）
* `一致` — パターンマッチング
* `無` — NULLポインタ

## 4. 基本型・変数・演算子

```ykn
変数 カウント: 整数 = 42;             # 64ビット符号付き整数 (i64)
変数 バイトデータ: バイト = 255;       # 8ビット符号なし整数 (u8)

変数 円周率: 浮動小数 = 3.14159;      # 64ビット浮動小数点数
変数 メッセージ: *バイト = "こんにちは！".ptr; # バイトポインタ
```

論理演算子:
* **かつ:** `かつ`, `and`, `ve`
* **または:** `または`, `or`, `veya`
* **否定:** `否定`, `not`, `degil`

## 5. 関数と制御フロー

### ハードウェア最適化ループ
ループ変数はプロセッサのレジスタ（`RBX`, `R12`..`R15`）に直接割り当てられます：

```ykn
関数 階乗(n: 整数) -> 整数 {
    変数 結果: 整数 = 1;
    変数 i: 整数 = 1;
    繰り返す i <= n {
        結果 = 結果 * i;
        i = i + 1;
    }
    戻す 結果;
}
```

## 7. データ付き列挙型とパターン一致

```ykn
列挙型 処理状態 {
    待機中,
    進行中(整数),    # 進捗率（%）を保持
    失敗(整数),      # エラーコードを保持
    完了(整数)       # 終了ステータスを保持
}

関数 状態を処理(s: 処理状態) -> 整数 {
    一致 s {
        処理状態.待機中 => {
            戻す 0;
        }
        処理状態.進行中(進捗) => {
            戻す 進捗;
        }
        処理状態.失敗(コード) => {
            戻す 0 - コード;
        }
        処理状態.完了(結果) => {
            戻す 結果;
        }
    }
}
```

## 9. 自己修復コンパイラエンジン（Self-Healing）

`--onar` または `--self-heal` を指定すると：
1. 自動的にバックアップファイル `.bak` を作成。
2. スペルミスを修正し、行末の `;` を補正。
3. 危険なポインタアクセスを検出しガードを自動注入：
   ```ykn
   もし ポインタ != 無 ならば {
       戻す ポインタ.値;
   }
   戻す 0;
   ```
4. 関数の末尾に `戻す 0;` を自動補完。
5. 修復結果が正しくコンパイルできるか即座に検証。

## 10. メモリ安全性とUse-After-Free検出

解放済みメモリへの再アクセスはコンパイル時に検知され、ブロックされます：
```ykn
bellek_serbest_birak(ptr); # メモリ解放

# 以降のアクセスでコンパイルエラー：
# ERROR: [UAF] 解放済みポインタへのアクセスを検出しました！
```

## 14. パッケージマネージャと2リポジトリ構造

1. **コンパイラコア:** `yukinary/yukinary`
2. **パッケージレジストリ:** `yukinary/packages`

`yukinary.toml`:
```toml
[package]
name = "my_app"
version = "0.1.0"
main = "main.ykn"
output = "build/app.exe"

[dependencies]
network = "1.0.0"
```

パッケージの追加：
```powershell
.\ykn_full.exe add network
.\ykn_full.exe build
```

## 15. 多言語コード変換（`#convert`）と外部ライブラリ連携（FFI）

YKNはエコシステム不足を補うため、強力な相互運用性（インフラ）を備えています：

### A. C-ABI FFI直接呼び出し（`harici isv`）
CやC++でコンパイルされた共有ライブラリ（Windowsの `.dll`、Linuxの `.so`）を直接呼び出し可能：

```ykn
harici isv sqlite3_open(ファイル名: *バイト, dbポインタ: **バイト) -> 整数;
harici isv sqlite3_close(dbポインタ: *バイト) -> 整数;
```

### B. `#convert` ディレクティブによるコード自動変換
ソースコード内に直接CやPythonのコードを埋め込み、YKNに自動トランスパイル：
* `#C-convert` — C/C++の関数や構造体をYKNに変換
* `#PY-convert` — Pythonの `def` 関数を型付きYKNコードに変換
* `#JS-convert` — JavaScriptコードを変換

### C. 2段階SHA-256キャッシュ（`.ykn_cache/convert/`）
変換されたコードはSHA-256シグネチャでキャッシュされ、再コンパイル時は0msのオーバーヘッドで即座にビルドされます。

## 16. ビルド検証とテスト実行

統合テストスクリプトの実行：
```powershell
powershell -ExecutionPolicy Bypass -File scratch/verify_all.ps1
```
Windows PE32+ および Docker Linux ELF64 の全テストが **終了コード 0** で合格します。
