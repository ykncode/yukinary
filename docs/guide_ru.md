## 1. Введение и архитектурная философия

**Yukinary (YKN)** — это независимый, самодостаточный (self-hosting) системный язык программирования и нативный компилятор, создающий исполняемые файлы для Windows (PE32+) и Linux (ELF64) напрямую, без внешних сред C-runtime (libc/msvcrt), без LLVM и сторонних линковщиков.

### Ключевые преимущества:
* **Прямая кодогенерация:** Мгновенная компиляция в машинный код без промежуточных шагов.
* **Безопасность памяти без GC:** Проверка времени жизни указателей и защита от Use-After-Free во время компиляции.
* **Родная поддержка русского языка:** Ключевые слова на русском языке парсятся компилятором на глубинном уровне.
* **Автоматическое исправление ошибок:** Компилятор сам дописывает пропущенные точки с запятой, фигурные скобки и расставляет проверки на null (`null-guard`).
* **Встроенная 16-КБ нейросеть:** Сверхбыстрая языковая модель BitNet 1.58b прямо внутри исполняемого файла компилятора.

## 2. Установка и быстрый старт

### Компиляция на Windows
```powershell
# Компиляция программы в бинарный файл PE32+
.\ykn_full.exe privet.ykn -o privet.exe

# Запуск
.\privet.exe
```

### Компиляция на Linux (Native или Docker)
```bash
# Компиляция в бинарный файл ELF64
./ykn_full privet.ykn -o privet
chmod +x privet
./privet
```

## 3. Многоязычный синтаксис

В Yukinary вы можете писать код на русском языке с полной поддержкой родных ключевых слов:

```ykn
функция сложить(а: целое, б: целое) -> целое {
    переменная результат: целое = а + б;
    если результат > 10 то {
        вернуть результат;
    } иначе {
        вернуть 0;
    }
}
```

### Таблица соответствия:
* `функция` — объявление функции
* `переменная` — объявление переменной
* `если` .. `то` .. `иначе` — условные переходы
* `пока` — цикл
* `вернуть` — возврат значения
* `структура` — пользовательская структура данных
* `перечисление` — перечисление (алгебраический тип)
* `сопоставление` — сопоставление с образцом (pattern matching)
* `пусто` — нулевой указатель (null)

## 4. Базовые типы, переменные и операторы

```ykn
переменная счетчик: целое = 100;           # 64-битное целое число (i64)
переменная байт_данных: байт = 255;        # 8-битное беззнаковое (u8)
переменная флаг: логическое = истина;     # Логический тип (истина / ложь)
переменная число_пи: дробное = 3.14159;   # Число с плавающей точкой
переменная текст: *байт = "Привет YKN!".ptr; # Указатель на байты
```

Логические операторы:
* **И:** `и`, `and`, `ve`
* **ИЛИ:** `или`, `or`, `veya`
* **НЕ:** `не`, `not`, `degil`

## 5. Функции и управление потоком исполнения

### Циклы с аппаратной оптимизацией
Переменные цикла компилятор напрямую привязывает к регистрам процессора (`RBX`, `R12`..`R15`):

```ykn
функция сумма(до: целое) -> целое {
    переменная итог: целое = 0;
    переменная i: целое = 1;
    пока i <= до {
        итог = итог + i;
        i = i + 1;
    }
    вернуть итог;
}
```

## 7. Перечисления с данными и сопоставление с образцом

```ykn
перечисление СтатусЗадачи {
    Ожидание,
    ВПроцессе(целое),    # Несет процент выполнения
    Ошибка(целое),       # Несет код ошибки
    Завершено(целое)     # Несет результат
}

функция обработать(с: СтатусЗадачи) -> целое {
    сопоставление с {
        СтатусЗадачи.Ожидание => {
            вернуть 0;
        }
        СтатусЗадачи.ВПроцессе(процент) => {
            вернуть процент;
        }
        СтатусЗадачи.Ошибка(код) => {
            вернуть 0 - код;
        }
        СтатусЗадачи.Завершено(результат) => {
            вернуть результат;
        }
    }
}
```

## 9. Система самовосстановления кода (Self-Healing)

При флаге `--onar` или `--self-heal`:
1. Автоматически создается снимок файла `.bak`.
2. Исправляются опечатки в словах и добавляются пропущенные `;`.
3. Вставляются динамические проверки указателей (null-guard):
   ```ykn
   если указатель != пусто то {
       вернуть указатель.значение;
   }
   вернуть 0;
   ```
4. Если функция заканчивается без возврата, добавляется `вернуть 0;`.
5. Все исправления проходят проверку тестовой компиляцией.

## 10. Контроль безопасности памяти и Use-After-Free

Компилятор отслеживает освобожденную память. Если после `bellek_serbest_birak(указатель)` код снова обращается к этому адресу, компилятор останавливает сборку:
```
ОШИБКА: [UAF] Обнаружен доступ к освобожденной памяти!
```

## 11. Изолированная среда безопасности (Sandbox Gate)

Любой сторонний код проверяется перед компиляцией:
* Запрещены несанкционированные сетевые вызовы (`socket`, `connect`, `send`).
* Запрещен запуск системных процессов (`CreateProcess`, `execve`).
* Запрещена подгрузка внешних DLL/so библиотек (`LoadLibrary`, `dlopen`).

## 12. Встроенная нейросеть: Micro-LLM

В компилятор встроена 16-килобайтная языковая модель **BitNet 1.58b**:
* Не требует видеокарты или интернета.
* Срабатывает за 0.1 мс при анализе контекста и автодополнении кода.
* Поддерживает внешние модели GGUF через `--llm-model модель.gguf`.

## 14. Пакетный менеджер и архитектура двух репозиториев

1. **Компилятор и среда выполнения:** `yukinary/yukinary`
2. **Центральный реестр пакетов:** `yukinary/packages`

В файле `yukinary.toml`:
```toml
[package]
name = "мой_сервис"
version = "0.1.0"
main = "main.ykn"
output = "build/app.exe"

[dependencies]
math = "1.0.0"
```

Команда добавления:
```powershell
.\ykn_full.exe add math
.\ykn_full.exe build
```

## 15. Конвертер кода (`#convert`) и внешний интерфейс функций (FFI)

Yukinary позволяет подключать библиотеки C/C++ и транспилировать код с других языков:

### А. Нативный FFI (`harici isv`)
Прямой вызов скомпилированных функций C без накладных расходов:

```ykn
harici isv sqlite3_open(имя_файла: *байт, указатель_бд: **байт) -> целое;
harici isv sqlite3_close(указатель_бд: *байт) -> целое;
```

### Б. Директивы `#convert`
Вставка исходного кода на C, Python или JS прямо в файл `.ykn`:
* `#C-convert` — транспиляция структур и функций C в YKN
* `#PY-convert` — трансляция Python-функций в типизированный код YKN
* `#JS-convert` — конвертация логики JavaScript

Пример:
```ykn
#PY-convert
def square(x):
    return x * x
#end-convert
```

### В. Кэширование SHA-256 (`.ykn_cache/convert/`)
Результаты конвертации сохраняются в кэше, предотвращая повторную трансляцию при сборке.

## 16. Сборка и кросс-платформенная верификация

Полная проверка выполняется одной командой:
```powershell
powershell -ExecutionPolicy Bypass -File scratch/verify_all.ps1
```
Все тесты проходят с кодом возврата **0** на Windows PE32+ и Linux ELF64 (Docker).
